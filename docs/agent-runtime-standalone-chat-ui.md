# 独立 SDK 示例对话界面

## 范围

本增量仅调整 standalone 宿主页面，不修改既有 app/web，也不覆盖已冻结的
0.1.0 发行包与历史验收结论。当前工作区的新源码需要单独验证，旧 manifest 只对应
旧发行快照，不宣称本增量已通过全部 P05 发布矩阵。

## 交互规格

- Harness 客户端风格的深色中性工作台：会话导航、中央对话流与底部输入区；
  不新建右侧计划栏。用户气泡靠右、Agent 气泡靠左；移动端保持单列可读。
- Enter 发送，Shift+Enter 换行；输入法组合期间的 Enter、keyCode=229、按键重复
  不发送。compositionend 与紧随的同次 Enter 不得误提交；释放该键后下一次 Enter
  才可发送。中英文候选确认遵循相同规则，不按文本内容分类。
- 点击发送和快捷键共用表单提交；提交中禁止重复发送。网络失败保留原请求身份和
  输入内容，切会话或用户继续输入时不得被旧响应清空。
- 思考来自已授权 analysis 通道，以原生 details 折叠，可实时展开查看；没有真实
  思考内容不造占位文字。思考与正文不合并，历史与实时复用 Journal 投影。
- 正文随已持久化 SSE 增量直接更新，不等待终态，也不添加逐字播放缓冲。
  用户位于底部时跟随输出；向上阅读时不强制拉回。切会话重置跟随状态。
- 状态、计划步骤与工具进展来自真实 Journal，不从用户文本猜测；控制、审批、
  资料预览/下载保持现有授权和幂等语义。
- 示例 thinking 通过启动配置开启，不允许页面自行提升受限事件读取权限。

## 验证

需执行 Node 键盘组合/Journal 回归与浏览器桌面、移动端验证。浏览器需检查
IME 确认不发请求、下一次 Enter 只发一次、Shift+Enter 换行、重复发送防护、
真实模型 analysis/content 分通道递增与刷新恢复。截图仅放 output/playwright。
自动事件无法证明所有操作系统原生输入法行为，仍需用户对本机输入法手工复核。

## 本轮实现与验证记录

- 实现：`examples/standalone/src/centn_example/ui/` 中的 index.html、style.css、
  app.mjs、composer.mjs；API 静态白名单显式增加 composer.mjs，不开放任意文件。
- Node：原有 Journal 13 项与新增键盘组合5项，合计18 passed；宿主资源路由7项与
  依赖错误处理7项，合计14 passed。Ruff、JS语法与 git diff --check 通过。
- 真实浏览器、Qwen thinking：输入法组合确认不提交，下一次 Enter 仅一次POST，
  Shift+Enter换行，重复按键不增加提交。正文在 streaming 状态观察到
  2/59/109/160/205/257/306/347 字符八次增长，analysis有32个不同非零长度，
  不是播放已完成答案。此次思考首片约15.6秒，正文首片约120.3秒，不能将界面改版
  说成模型延迟优化，也不构成性能SLA。
- 桌面1440×1000和移动390×844截图已人工查看；无横向溢出，思考折叠可操作，
  刷新重新授权后正文及思考原文均完全一致。截图和探针代码位于
  `output/playwright/p05-chat-ui/`，不入发行包。
- 第一次有头浏览器采样页在操作中被刷新，内存探针丢失；未计为完整回放验证，
  已在隔离浏览器重新验证以上结果。初次pytest缺显式源码路径导致收集失败，
  按示例实际PYTHONPATH重跑14项通过；未掩盖失败或计入通过数量。
- 本地示例启动配置开启 thinking，仍由宿主设置和ACL授权；没有开放任意客户端
  请求受限事件。SDK核心状态、数据库模型、事件协议和已发行包不变。
- 未重跑整个P05发布矩阵，不重写0.1.0的原始发行manifest；本增量未发布新包。
